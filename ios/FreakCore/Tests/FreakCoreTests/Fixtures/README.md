# Golden parity vectors

`vectors/*.json` are generated by the **Python reference implementation**
(the `microfreak` package at the repo root) and are AUTHORITATIVE: the Swift
port must produce and parse byte-identical frames. Swift only consumes these
files — it never regenerates or reshapes them, and Swift tests never
re-derive expected bytes by hand.

```bash
# regenerate, from the repo root (offline; SimulatedMicroFreak only, no MIDI)
python3 tools/gen_vectors.py
```

The generator is fully deterministic: fixed seeds (blobs are
`_synth_blob(seed, label)` sha256 streams), a fake clock driving the
`Session` (sleep advances virtual time by `max(dt, 1e-4)`), stable JSON key
order. Running it twice produces byte-identical files.

## Conventions (every file)

- Top-level object is exactly `{"description": str, "cases": [...]}`.
  `description` restates the file's contract and the regeneration command.
- **All byte sequences are space-separated uppercase two-digit hex**
  (`"F0 00 20 6B 07 01 ..."`). Blobs are always exactly 4672 bytes
  (9344 hex digits + separators); every frame starts `F0 00 20 6B 07 01`
  and ends `F7` (asserted by the generator's own verify pass).
- `meta` is always the 9 bytes of long-0x52 `payload[3..11]`, hex as above.
- Absent/unknown is JSON `null` (e.g. a failed name read).
- **Transcripts**: `transcript` is every wire frame in order, both
  directions, as `{"dir": "out"|"in", "label": str, "seq": int,
  "frame": hex}` — `"out"` = host → device, `"in"` = device → host (mfcap
  house convention). Long-0x52 entries additionally carry `"slot"` and
  `"name"` (the decoded reply). Labels: `read_name_req`, `open_dump_req`,
  `pull_next_req`, `ack`, `name_write`, `name_reply`, `open_write`, `go`,
  `chunk`, `last_chunk`. `TranscriptTransport` (TestSupport.swift) replays
  the device side: every host frame must byte-match the next `out` entry,
  then queued `in` entries become receivable.
- Extra annotation keys (`note`, `source`, counts, seq lists) may appear on
  any case; consumers must ignore keys they don't know. But files must not:
  `VectorTests.everyVectorFileIsHandled` fails on any `vectors/*.json`
  without a runner, and the frame-builder/reply-lag runners fail on an
  unknown `kind` — a new vector can never be silently skipped.

## Files

### `frames.json` — every pure frame builder

Cases dispatch on `"kind"`:

- `read_name_req`, `open_dump_req`, `open_write_frame`:
  `{kind, slot, bank, pos, seq, frame}` — `frame` is the exact wire bytes
  for the builder at that `(seq, slot)`. Slots covered:
  `[0, 8, 40, 127, 128, 200, 383, 384, 509, 511]` (bank boundaries 127/128,
  the payload[9] reply boundary 383/384, both extremes, the hardware-fixture
  and gate slots).
- `pull_next_req`: `{kind, seq, frame}` — host pull: len `0x01`, payload
  `[0x00]` (distinct from the device's empty-payload ack).
- `go_frame`: `{kind, seq: 0, frame}` — seq 0, len 0, empty payload, always.
- `name_write_frame`: `{kind, slot, bank, pos, seq, name, meta,
  expected_payload: {p3, p8, p9}, frame}`. Inputs include reply-form meta
  (the 0x10 bit set for slots ≥ 128, junk in `meta[5]`/`meta[6]`) plus
  explicit variants (a hardware reply's meta verbatim, the 0x10 bit on a
  low slot, all-0x7F), and names from empty through 1-char to the 23-char
  maximum. `expected_payload` pins the direction-dependent recompute:
  `payload[3] = meta[0] & ~0x10`, `payload[8] = pos`,
  `payload[9] = 0x06` (constant on every outbound write).
- `chunk_frames` (one case): `{kind, blob_seed, blob_label, blob_hex,
  blob_sha256, chunk_count: 146, chunk_seqs, frames: [146 hex frames]}`.
  The blob is `_synth_blob(2026, "chunk-frames")`. 145 × `0x16` + 1 ×
  `0x17`, len byte `0x20`, 32 payload bytes each; `chunk_seqs[i] ==
  (i + 1) % 128` — continuing from the go frame's 0 and wrapping THROUGH 0.
  No address, no checksum, anywhere.

### `name_replies.json` — long-0x52 reply decoding

`{slot, source, payload, frame, expected: {slot, name, meta}}` per case.
`payload` is the 35-byte long-0x52 payload; `frame` wraps it with seq
`0x00` and the realistic len byte `0x23` (the parser does not validate the
len byte). `expected` is `decode_name_reply`'s output: the embedded slot
(`payload[0..1]` — the ONLY valid way to match a reply), the decoded name
(`payload[12:]` split at first NUL, printable-ASCII filtered, stripped),
and `meta` = `payload[3..11]` verbatim.

- `source: "hardware-2026-09-01"` — the five captured payloads (slots 0, 8,
  40, 200, 511), verbatim from `tests/test_sysex.py`. Slot 200 carries
  category `0x03` / attribute `0x11`; slots ≥ 128 carry the reply-only
  0x10 flag in `meta[0]`.
- `source: "synthetic-factory_fresh(seed=0)"` — sim-rendered replies for the
  boundary slots 0, 127, 128, 383, 384, 511: 127→128 flips the 0x10 flag in
  `meta[0]`; 383→384 flips the high-bank flag in `meta[6]` (reply
  payload[9]).

### `write_burst.json` — the raw 7-frame write sequence

Two cases (slot 3 and slot 509 — one per side of the 384 boundary):
`{slot, name, meta, blob_hex, blob_sha256, chunk_count, control_seqs,
chunk_seqs, expected_ack_count: 149, readback: {slot, name, meta},
transcript}`. Captured from a **fresh** `Session.write_preset` (first
addressed seq = 1) over `factory_fresh(reply_lag=False)`: read-name +
reply, long 0x52 + ack, short 0x52 open + ack, go (seq 0) + ack, 146 chunks
each acked with an empty-payload seq-echoing `0x18` (149 acks total
including the 3 control-frame acks), read-back + reply. The input `meta` is
reply-form, so the outbound long 0x52 must clear 0x10, recompute
payload[8], force payload[9] = 0x06.

### `write_conversation.json` — one complete VERIFIED write

One case, slot 300: everything in `write_burst` PLUS the verify read-back —
`MicroFreak.write(slot, preset, verify=True)`, i.e. the 7-frame sequence
followed by a full dump (open, unanswered; 146 pull/chunk lockstep pairs)
whose reassembled blob must sha256-match what was sent.
`{slot, name, meta, blob_seed: 7, blob_label: "write-conversation",
blob_hex, blob_sha256, report: {slot, sha256, name, verified: true},
counts: {out_frames: 298, in_frames: 297, write_acks: 149,
verify_chunks: 146}, transcript}`. Session seqs: 1 (read), 2 (name write),
3 (open), 4 (read-back), 5 (dump open), pulls 6..127 then 1..24 — the
addressed counter skips 0; the go/chunk stream is 0 then `(i+1) % 128`,
wrapping through 0. Replayed in Swift by driving
`MicroFreakDevice.write` over a `TranscriptTransport`.

### `device_state.json` — the deterministic factory state

One case: `{seed: 0, init_copies: 269, slots: 512, named_slots: 243,
init_blob_sha256, distinct_sha_count: 244, expected_expendable:
{first_slot: 243, count: 269}, state}`. `state` maps zero-padded slot
(`"000"`…`"511"`, ascending) to `{name, sha256, meta}` for
`SimulatedMicroFreak.factory_fresh(seed=0, init_copies=269)`:

- slots 0..242: distinct presets `"Patch NNN"`, blob
  `_synth_blob(0, "slot<NNN>")`;
- slots 243..511: 269 byte-identical factory `"Init"` duplicates of
  `_synth_blob(0, "init")`;
- meta is reply-form and positionally correct: 0x10 flag in `meta[0]` for
  slots ≥ 128, `meta[5]` = pos, `meta[6]` flips 0→1 at slot 384.

A Swift `factoryFresh` with the same seed must reproduce every name, sha
and meta byte (pinning `synthBlob` parity), and `findExpendable`
(threshold 3) must return exactly slots 243..511 — content-based
expendability, never a `name == "Init"` match.

### `read_dump.json` — read/dump conversations

`{slot, reply_lag, [name_info: {slot, name, meta}], pull_seqs, chunk_count,
blob_hex, blob_sha256, transcript}`. Case 1 (slot 200, lag off): name read
+ reply, then the dump. Case 2 (slot 511, lag ON — dumps are unaffected by
name-reply lag): dump only. Strict lockstep: open `[bank,pos,0x01]`
(unanswered), then 146 × (pull-next → chunk), each chunk echoing its pull's
seq. `pull_seqs` walks 1..127 wrapping and **skipping 0**.

### `reply_lag.json` — the lag hazard and its defense

Cases dispatch on `"kind"`:

- `raw_wire_lag`: `{kind, requests: [{seq, slot}],
  reply_after_each_request: [null | {reply_slot, name, reply_seq}],
  transcript, note}` — raw sends against the lagged sim: reply N is held
  until request N+1; the released reply echoes its OWN request's seq and
  embedded address.
- `session_scrambled_order`: `{kind, read_order, results:
  [{requested_slot, name, meta}], reads, name_requests_sent, transcript,
  note}` — a full `Session` transcript over scrambled slots with revisits;
  embedded-address matching labels every slot correctly, and
  `name_requests_sent > reads` proves the retry defense engaged.

### `sync_diff.json` — the pure diff decision table

`{name, threshold, records: [{slot, name, sha256}], library:
[{slot, name, sha256}], expected: [{slot, status, status_name}] |
expect_error: "ValueError", note}`. `threshold: null` means the default
`DUPLICATE_THRESHOLD` = 3. Status strings: `in_sync`, `added`
(DEVICE_ONLY), `missing` (LIBRARY_ONLY), `changed` (DIFFERS), `empty`.
Includes a case producing all five statuses, a threshold override flipping
expendability, and the hash-less snapshot refusal.

### `expendable.json` — content-based expendability

`{name, threshold, records: [{slot, name, sha256}], expected_expendable,
note}`. `sha256` values here are symbolic tokens — only string equality
matters. Pins: the 2-vs-3 duplicate boundary, blank/whitespace names,
`name: null` (read FAILED) never expendable by name but still countable by
content, `sha256: null` never expendable, and `"Init"`-named unique blobs
NOT expendable.

## Consumers

`VectorTests.swift` runs every file (and fails on unhandled ones);
`TestSupport.swift` holds the hex codecs, `TestClock` (the FakeClock twin)
and `TranscriptTransport`. Vectors are bundled via the test target's
`resources: [.copy("Fixtures")]` in `Package.swift`.
